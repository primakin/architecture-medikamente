# Проблемные зоны
- Нарушение принципа минимизации данных - не определена цель сбора расширенной анкеты, дублирование платежной информации.
- Данные хранятся, передаются и обрабатываются в открытом виде, отсутствуют механизмы шифрования, анонимизации и псевдонимизации в процессах обработки данных.
- Отсутствует управление жизненным циклом данных - не определены политики хранения и удаления данных.
- Отсутствует контроль доступа к данным, хранящимся в файловой системе - не реализован RBAC/ABAC.
- Не разработаны процедуры безопасного удаления или анонимизации данных, которые больше не нужны.
- Политики конфиденциальности отсутствуют/не опубликованы.
- Пользователи не контролируют настройки конфиденциальности и не имеют доступа к своим данным.
- Отсутствуют процессы протоколирования и мониторинга для проведения аудита обработки данных.
- Не реализовано получение информированного согласия пользователей перед сбором или обработкой их данных.

# Обеспечение безопасности данных
данные - защита (шифрование/обфускация/обезличивание) - теги

## Персональные данные
Список данных:

- ФИО;
- дата рождения;
- телефон;
- электронная почта;
- адрес прописки;
- место работы/учебы.

Меры защиты:

- Шифрование at rest (AES-256) хранилища данных пользователей
- Шифрование in transit (TLS 1.3) для будущих API
- Обфускация в UI при отсутствии прав на просмотр, а также в логах и среде разработки
- RBAC (доступ у администраторов и специалистов)

## Медицинские данные
Список данных:

- журнал приема пациентов;
- хронические заболевания;
- назначения специалистов; 
- диагнозы;
- результаты обследований и анализов.

Меры защиты:

- Шифрование at rest (AES-256) хранилища медицинских карт и журналов приема пациентов
- Шифрование in transit (TLS 1.3) для будущих API
- Обфускация в UI при отсутствии прав на просмотр, а также в логах и среде разработки
- Обезличивание для аналитики и ML (замена ФИО на идентификаторы)
- RBAC (доступ только у лечащего врача)

## Финансовые данные
Список данных:

- информация о платежах и услугах;
- информация о ТМЦ.

Меры защиты:

- Шифрование at rest (AES-256) хранилища финансовых данных (Excel и 1C)
- Шифрование in transit (TLS 1.3) при передаче данных между системами
- RBAC (доступ только у сотрудников бухгалтерии/склада)
- Обфускация в UI при отсутствии прав на просмотр, а также в логах и среде разработки
